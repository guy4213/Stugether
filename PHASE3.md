# PHASE 3 — Change Requests ומסלול סקייל

**מה זה המסמך:** כל מה ש**נחתך במכוון** מה-MVP כדי להיכנס ל-70 השעות, וכל מה שנדרש כשהמערכת תגדל.

**זה לא רשימת באגים ולא חוב טכני שנוצר בהיסח הדעת.** כל סעיף כאן הוא החלטה מודעת, עם תיאור מדויק של מה חסר, מה המחיר בפועל, ואיך מממשים.

---

## חלק א׳ — מה נחתך מה-MVP

### 1. Rolling summary להקשר ה-AI

|                 |                                                                                                                                                                                                                    |
| --------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **מה יש היום**  | 30 ההודעות האחרונות + תקרת tokens קשיחה                                                                                                                                                                            |
| **מה חסר**      | בשיחה ארוכה ה-AI "שוכח" את תחילת הדיון                                                                                                                                                                             |
| **מתי זה כואב** | חדר עם 100+ הודעות. הסטודנט מזכיר משהו מההתחלה וה-AI לא מבין                                                                                                                                                       |
| **המימוש**      | טבלת `room_summaries(room_id, summary, covers_up_to_message_id, tokens)`. כשמצטברות מעל X הודעות מאז הסיכום האחרון, נורית קריאת סיכום אסינכרונית אחרי סיום הריצה. ההקשר הופך ל-`[prompt] + [סיכום] + [הודעות מאז]` |
| **הערכה**       | ~5ש׳ + עלות טוקנים נוספת לכל סיכום                                                                                                                                                                                 |

|                 |                                                                                                                                                   |

### 3. Cron watchdog לריצות תקועות

|                 |                                                                                   |
| --------------- | --------------------------------------------------------------------------------- |
| **מה יש היום**  | stale-check lazy בתוך `start_ai_run` — ריצה תקועה משתחררת כשמישהו מנסה שוב        |
| **מה חסר**      | שחרור אוטומטי. חדר שבו כולם ויתרו נשאר עם `ai_run` תקוע ב-`running`               |
| **מתי זה כואב** | בעיקר בנתוני האדמין — ריצות `running` נצחיות מזהמות את הסטטיסטיקה                 |

### 4. Custom Access Token Hook

|                 |                                                                                                                                       |
| --------------- | ------------------------------------------------------------------------------------------------------------------------------------- |
| **מה יש היום**  | `is_super_admin()` עושה `SELECT` ל-`profiles` בכל הערכת policy                                                                        |
| **מה חסר**      | ה-role לא יושב ב-JWT, ולכן יש lookup ל-DB בכל בדיקה                                                                                   |
| **מתי זה כואב** | רק בקנה מידה גדול. במאות משתמשים ההבדל לא נמדד                                                                                        |
| **המימוש**      | Supabase Custom Access Token Hook שמעתיק את `profiles.role` ל-JWT claim. ה-policies קוראות `auth.jwt()->>'user_role'` במקום לגעת ב-DB |
| **הערכה**       | ~2ש׳ (כולל טיפול ב-role שהשתנה לפני שה-token התחדש)                                                                                   |

### 5. הזמנות במייל ובלינק

|                 |                                                                                                                                                                                              |
| --------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **מה יש היום**  | הזמנה רק למשתמש **רשום** שנרשם **לאותו קורס**, in-app                                                                                                                                        |
| **מה חסר**      | אי אפשר להזמין חבר שעוד לא נרשם לפלטפורמה                                                                                                                                                    |
| **מתי זה כואב** | **זה הצוואר בקבוק של הצמיחה.** סטודנט שרוצה ללמוד עם חבר חייב שהחבר ייכנס וירשם לקורס קודם                                                                                                   |

## חלק ג׳ — מסלול סקייל

הלקוח עשוי להפוך לשותף. לכן צריך **מסלול יציאה** מ-Supabase Cloud שלא מחייב כתיבה מחדש — **בלי לשלם על זה שום דבר היום**.

### יעדים

| יעד                                          | מתי                                          | מה נשאר זהה                                                                    |
| -------------------------------------------- | -------------------------------------------- | ------------------------------------------------------------------------------ |
| **Supabase self-hosted** (Docker) על Hetzner | כשהחשבון ב-Supabase Cloud מצדיק את זה כלכלית | Auth, Realtime, RLS, המיגרציות — **אותו קוד**. זה אותו Supabase, רק מתארח אחרת |
| **Cloudflare R2** לקבצים כבדים               | רק אם ייכנסו חומרי למידה                     | egress בעלות אפס, בניגוד ל-S3 ול-Supabase Storage                              |

### תנאי סף למעבר

**לא עוברים בלי כל החמישה:**

1. **גיבויים מחוץ לשרת** — לא על אותה מכונה
2. **בדיקת שחזור שהורצה בפועל** — גיבוי שלא שוחזר מעולם הוא הנחה, לא גיבוי
3. **ניטור** — uptime, דיסק, חיבורי DB
4. **עדכוני אבטחה שוטפים** — OS ו-Docker images
5. **מי אחראי לתחזוקה — בשם ובכתב**

המעבר מחליף חשבון מנוהל בתחזוקת שרת. **זו החלטה תפעולית, לא טכנית.** החיסכון הכספי אמיתי, אבל הוא קונה עבודה.

### מה כבר נעשה היום כדי שהמעבר יהיה זול

שלושה גבולות בקוד. עלות שוליים כמעט אפס כשהם שם מיום 1, יקרים מאוד לרפקטר אחר כך:

| גבול                      | הכלל                                 | מה זה מאפשר                                                              |
| ------------------------- | ------------------------------------ | ------------------------------------------------------------------------ |
| `lib/repositories/`       | אין `supabase.from()` בקומפוננטות    | החלפת שכבת הנתונים במקום אחד                                             |
| `hooks/useRoomChannel.ts` | אין `supabase.channel()` בקומפוננטות | מעבר מ-postgres_changes ל-broadcast, או לספק realtime אחר, בלי לגעת ב-UI |
| `lib/storage/`            | אין `supabase.storage` בקומפוננטות   | מעבר ל-R2 = שינוי בקובץ אחד                                              |

**נאכף ב-ESLint** (`no-restricted-imports`), לא בכוונה טובה. בלי הכלל הזה הגבול נשחק תוך שבועיים — הראשון שיכתוב `supabase.from()` בקומפוננטה כדי "לחסוך רגע" פותח את הסכר.

### שיקולי סקייל נוספים

| נושא                          | מתי זה יהפוך לבעיה     | פתרון                                                                            |
| ----------------------------- | ---------------------- | -------------------------------------------------------------------------------- |
| `postgres_changes` ב-Realtime | מאות מנויים בו-זמנית   | `realtime.broadcast_changes()` מטריגר. **בלי שינוי ב-UI** בזכות `useRoomChannel` |
| ספירת unread ב-`COUNT(*)`     | עשרות אלפי הודעות לחדר | טבלת rollup או counter עם trigger                                                |
| `maxDuration=60` ב-Vercel     | תשובות AI ארוכות יותר  | שדרוג תוכנית, או העברת מסלול ה-AI ל-worker ייעודי                                |
| טעינת קטלוג ידנית             | מוסד שני והלאה         | ייבוא CSV (חלק א׳ §9)                                                            |

## נוהל

1. כל פריט כאן הוא **הצעת מחיר נפרדת**, לא "עוד קצת עבודה".
2. פריט שהלקוח מבקש עובר ל-`TASKS.md` **רק אחרי אישור בכתב** של ההיקף והמחיר.
3. באג = סטייה מ-`SPEC.md`. **מה שמופיע כאן אינו באג** — הוא נחתך במכוון והוסכם.
